# Verilog System Breakdown

The Verilog directory represents your actual FPGA hardware. It is split into three files: the core math engine (`orb_pyr_scaler.v`), the top-level wrapper (`orb_image_pyramid.v`), and the verification testbench (`TBImagePyramid.v`).

---

## 1. `orb_pyr_scaler.v` (The Core Engine)
This module shrinks a single image stream by 1.2x. It operates in a 5-stage pipeline (doing a little bit of math on each clock cycle to maintain high speed).

### Stage 0: Coordinates
```verilog
cx  <= cx + 16'd1;
cx6 <= (cx6 == 3'd5) ? 3'd0 : cx6 + 3'd1;
```
* **Explanation:** Every time a valid pixel arrives, the X counter (`cx`) goes up. The `cx6` counter goes 0, 1, 2, 3, 4, 5, then loops back to 0. This tracks our modulo math without using expensive division hardware.

### Stage 1: The Line Buffer and 2x2 Window
```verilog
s1_top <= lb[cx];
lb[cx] <= in_pixel;
```
* **Explanation:** `lb` is a Block RAM that holds an entire row of the image. When a new pixel arrives (`in_pixel` at row Y), we read the pixel at the exact same X coordinate from the previous row (`s1_top` at row Y-1). We now have access to a 2x2 square in a single clock cycle.

### Stage 2 & 3: Weights and Multiply-Accumulate (MAC)
```verilog
wire [5:0] w00 = wx0 * wy0;  // ... calculates weights
p00 <= wp_top * w00;         // Multiplies pixel by weight
acc3 <= p00 + p01 + p10 + p11; // Stage 3: Adds them up
```
* **Explanation:** Calculates the window weights using the modulo-6 counters. It multiplies each of the 4 pixels in the 2x2 window by its respective weight, then adds all four results into a 13-bit accumulator (`acc3`).

### Stage 4: Normalization
```verilog
wire [12:0] nrm  = acc3 + RND;               
wire [25:0] prod = nrm * 13'd5243;           
wire [7:0]  pix  = prod[24:17];
```
* **Explanation:** Dividing by 25 in hardware is very slow. Instead, the hardware multiplies by `5243` and shifts right by 17 bits. (Mathematically, $5243 / 2^{17} \approx 1 / 25$). This gives us our exact final pixel value.

## 2. `orb_image_pyramid.v` (The Wrapper)
```verilog
orb_pyr_scaler #(.IMG_W(IMG_W)...) u_scaler1 (...);
orb_pyr_scaler #(.IMG_W(W1)...) u_scaler2 (...);
```
* **Explanation:** This file simply instantiates (creates copies of) the `orb_pyr_scaler` module three times. 
* It wires the output of `u_scaler1` directly into the input of `u_scaler2`. This means as Level 1 is being generated, it immediately starts generating Level 2. All pyramid levels are computed concurrently, saving massive amounts of time and memory.

## 3. `TBImagePyramid.v` (The Testbench)
This is the simulation referee. It is not synthesized into actual hardware.

### Memory Initialization
```verilog
$readmemh("../pyCodes/imageTest/level0_pixels.hex", img);
```
* **Explanation:** Reads the `.hex` text files generated by Python and loads them into virtual memory arrays inside the simulator.

### The Stimulus Block (The "Camera")
```verilog
in_valid <= 1'b1;
in_pixel <= img[i];
@(posedge clk);
```
* **Explanation:** This loops through the input image array (`img`). On every rising edge of the clock (`@(posedge clk)`), it pushes one pixel into the DUT (Device Under Test), simulating a continuous video stream.

### The Verification Block (The "Checker")
```verilog
if (l1_pixel !== e1[c1 % N1]) begin
    err = err + 1;
    $display("L1 pix mismatch...");
end
```
* **Explanation:** Runs parallel to the stimulus block. Every time the DUT outputs a valid pixel (`l1_valid`), the testbench checks if `l1_pixel` exactly matches the expected pixel `e1` (which was loaded from Python). If they don't match, it flags an error.
